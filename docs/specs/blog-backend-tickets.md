# 博客后端六个限界上下文工单草案

> 状态：已发布至 GitHub Issues [#2–#18](https://github.com/Tlfff/ai-blog/issues/1)
>
> 每张工单标签：`ready-for-agent`
>
> 关联规格：博客后端六个限界上下文重构规格

## 依赖顺序

`T01 → T02 → T03`，`T02 → T04 → T05 → T06/T07/T10/T13`，`T05 → T08 → T09/T11`，`T10 → T12`，`T13 → T14`，最终由 T15、T16、T17 完成开放接口和系统验收。

## T01 用户注册与公开资料（[#2](https://github.com/Tlfff/ai-blog/issues/2)）

**交付内容**：用户可以完成注册、查看自己的资料、查看他人公开资料并修改昵称和头像字段；该工单同时落地第一个完整的 Proto、应用服务、领域模型、仓储、迁移、依赖注入和测试纵向切片，为后续工单提供可复用范式。

**阻塞于**：无，可立即开始。

- [ ] 昵称和手机号保持唯一，密码使用既定 PBKDF2-SHA256 格式保存。
- [ ] 个人资料和公开资料严格区分私有字段，异常用户状态不可查询。
- [ ] HTTP 路由、请求响应和统一错误结构符合功能文档。
- [ ] 通过生成的 HTTP 服务接口验证成功、冲突、校验失败和资料更新行为。

## T02 用户登录、鉴权与退出（[#3](https://github.com/Tlfff/ai-blog/issues/3)）

**交付内容**：用户可以使用手机号或昵称登录，在多个设备保持独立会话，通过 Bearer Token 访问受保护接口，并只退出当前设备；普通用户不能访问管理员接口。

**阻塞于**：T01 用户注册与公开资料。

- [ ] 普通会话有效期为 7 天，`remember_me=true` 时为 30 天。
- [ ] Redis 保存 Token 会话和用户 Token 集合，Token 使用安全随机数生成。
- [ ] 覆盖 Token 缺失、格式错误、过期、不存在、可选登录和管理员角色校验。
- [ ] 退出只使当前 Token 失效，不影响其他设备会话。
- [ ] 登录时记录最后登录 IP 和时间，资料响应通过 IP 地址库将 `last_login_ip` 转换为地区文案。

**本地 IP 属地方案**：

- 沿用原项目 `blog-system/blog` 的 `github.com/lionsoul2014/ip2region/binding/golang`，版本固定为 `v0.0.0-20260630140118-a99989343ebd`；随服务部署 IPv4、IPv6 两份 XDB，不调用外部网络接口。
- 同时使用 `service.NewV4Config` 和 `service.NewV6Config` 初始化统一解析器，沿用 `BufferCache` 与 20 个 Searcher 的配置；不得只初始化 IPv4。两份数据约占 44 MiB，部署资源预算需包含这部分常驻内存。
- XDB 路径由 Leo 配置显式提供并在启动时校验，不依赖当前工作目录；缺失、损坏或版本不匹配时服务启动失败。解析器通过 Wire 注入，关闭函数交给应用生命周期统一释放。
- 对领域和应用层只暴露 `IPRegionResolver` 接口。登录时通过受信代理配置后的客户端 IP 写入原始 `last_login_ip`；个人资料、文章和评论响应复用解析器生成地区文案。
- 空地址、`localhost`、回环和私网地址返回“内网”；非法地址、查询失败或无有效数据返回“未知”；中国地址返回去掉“省/市”后缀的省级地区，缺少省份时返回“中国”；境外地址优先使用既有国家中文映射，未命中时返回原始国家名。
- 不增加无界进程级查询缓存，避免地址数量持续增长；离线内存查询本身作为快速路径。测试覆盖 IPv4、IPv6、内网、非法地址、国内外解析、资源路径不依赖工作目录、并发查询和资源关闭。

## T03 账号安全与头像上传（[#4](https://github.com/Tlfff/ai-blog/issues/4)）

**交付内容**：用户可以验证旧密码、使用一次性凭证修改密码、修改手机号，并通过 MinIO 预签名地址上传和确认头像。

**阻塞于**：T02 用户登录、鉴权与退出。

- [ ] 改密凭证有效期为 10 分钟，只能原子消费一次且必须属于当前用户。
- [ ] 修改密码后清理除当前设备外的其他会话。
- [ ] 修改手机号同时通过业务校验和唯一索引保证唯一。
- [ ] 头像对象 Key 必须属于当前用户路径，并保留不校验对象存在、不自动删除旧头像的兼容行为。

## T04 创建文章与正文图片（[#5](https://github.com/Tlfff/ai-blog/issues/5)）

**交付内容**：管理员作者可以获取正文图片上传凭证、使用稳定图片引用创建文章，并读取新文章的后台可编辑详情。

**阻塞于**：T02 用户登录、鉴权与退出。

- [ ] 正文图片通过 MinIO 直传，数据库保存未绑定图片记录和稳定对象信息。
- [ ] 创建文章与绑定全部正文图片在同一事务完成，图片不存在或已归属其他文章时整体回滚。
- [ ] 创建接口保持 2 秒防重复提交及当前返回契约。
- [ ] 后台详情返回正文、作者、图片映射和当前可用互动统计。

## T05 更新、发布与公开阅读（[#6](https://github.com/Tlfff/ai-blog/issues/6)）

**交付内容**：管理员作者可以更新并发布文章，访客和登录用户可以查看已发表文章详情，登录用户还能看到自己的点赞状态。

**阻塞于**：T04 创建文章与正文图片。

- [ ] 只有作者可以更新和发布文章，已删除文章不能更新。
- [ ] 更新时原子绑定新增图片并解绑移除图片，外部图片 URL 不参与关系同步。
- [ ] 只有已发表文章可以公开读取，游客固定返回未点赞状态。
- [ ] 发布和更新后文章表状态及字段满足后续搜索 Binlog 同步契约。

## T06 文章管理与垃圾箱（[#7](https://github.com/Tlfff/ai-blog/issues/7)）

**交付内容**：管理员作者可以分页筛选文章、将文章移入垃圾箱、查看垃圾箱、恢复为草稿，并彻底删除文章及其绑定对象。

**阻塞于**：T05 更新、发布与公开阅读。

- [ ] 后台列表兼容状态筛选、游标分页和 Offset 分页规则。
- [ ] 移入垃圾箱使用软删除状态，恢复目标固定为草稿。
- [ ] 只有作者可以恢复或彻底删除文章。
- [ ] MinIO 对象删除失败时保留数据库记录以便重试；成功时完成数据库硬删除。

## T07 文章列表、浏览与热榜（[#8](https://github.com/Tlfff/ai-blog/issues/8)）

**交付内容**：访客可以查看已发表文章列表和热榜；访问详情时异步增加浏览量，登录用户还会留下浏览历史。

**阻塞于**：T05 更新、发布与公开阅读。

- [ ] 公开列表只返回已发表文章，并兼容摘要截取及两种分页方式。
- [ ] 浏览事件发送失败不影响文章详情响应。
- [ ] 浏览消费者维护登录用户历史和文章浏览量，并具备重试、幂等及死信处理。
- [ ] Redis 返回热榜前 10，启动时和每小时可从 MySQL 权威数据重建前 100。

## T08 评论发布、回复与列表（[#9](https://github.com/Tlfff/ai-blog/issues/9)）

**交付内容**：登录用户可以发表主评论和楼中楼回复，访客可以分页查看主评论、回复及公开用户信息。

**阻塞于**：T02 用户登录、鉴权与退出；T05 更新、发布与公开阅读。

- [ ] 只允许评论有效文章，回复必须关联未删除的根评论。
- [ ] 回复统一直属根评论，并通过 `reply_to_user_id` 表达被回复者。
- [ ] 并发回复通过事务和行锁保持根评论回复数正确。
- [ ] 列表兼容游标/Offset 分页、只看楼主和点赞数投影读取。

## T09 评论删除与文章评论数（[#10](https://github.com/Tlfff/ai-blog/issues/10)）

**交付内容**：评论作者和管理员可以按权限删除评论；文章上下文最终一致地维护评论数量。

**阻塞于**：T08 评论发布、回复与列表。

- [ ] 用户只能删除自己的评论，管理员只绕过所有权校验。
- [ ] 删除主评论会级联软删除回复，删除回复只影响自身。
- [ ] 重复删除不会重复扣减回复数或文章评论数。
- [ ] 评论创建和删除事件通过 Outbox 发布，文章计数消费者处理重复和乱序消息后仍保持正确。

## T10 文章点赞与点赞数（[#11](https://github.com/Tlfff/ai-blog/issues/11)）

**交付内容**：登录用户可以幂等地点赞或取消点赞文章；点赞上下文保存事实关系，文章上下文最终一致地维护 `like_count`。

**阻塞于**：T02 用户登录、鉴权与退出；T05 更新、发布与公开阅读。

- [ ] 重复点赞或重复取消均按成功处理，不重复改变点赞事实。
- [ ] 点赞事实与 Outbox 在同一事务提交，缓存或即时发布失败不回滚事实。
- [ ] Redis 点赞集合可从 MySQL 重建。
- [ ] 文章计数消费者对重复和乱序事件幂等，计数不可为负。

## T11 评论点赞与点赞数（[#12](https://github.com/Tlfff/ai-blog/issues/12)）

**交付内容**：登录用户可以幂等地点赞或取消点赞评论；评论上下文最终一致地维护 `like_count`。

**阻塞于**：T02 用户登录、鉴权与退出；T08 评论发布、回复与列表。

- [ ] 只能操作存在且未删除的评论。
- [ ] 点赞关系、Outbox、缓存和评论计数投影遵循与文章点赞相同的可靠性规则。
- [ ] 评论计数投影可从点赞事实重建。
- [ ] 当前不生成评论点赞通知。

## T12 文章点赞通知（[#13](https://github.com/Tlfff/ai-blog/issues/13)）

**交付内容**：文章首次被他人点赞后，作者最终收到一条通知，并可以查看通知列表、未读数量和全部标记为已读。

**阻塞于**：T10 文章点赞与点赞数。

- [ ] 自己点赞自己的文章不生成通知，同一点赞事件最多生成一条通知。
- [ ] MongoDB 通知保存发送者昵称、头像和文章标题快照。
- [ ] 用户只能读取和修改自己的通知，分页规则符合功能文档。
- [ ] 只主动生成类型 1 通知，同时兼容读取类型 2～4 的存量文档。

## T13 Meilisearch 搜索与增量同步（[#14](https://github.com/Tlfff/ai-blog/issues/14)）

**交付内容**：文章表新增、更新或删除后，Meilisync 将变更同步到 Meilisearch；访客可以搜索已发表文章并获得高亮标题和正文摘要。

**阻塞于**：T06 文章管理与垃圾箱。

- [ ] Meilisync 订阅 `articles` 表 INSERT、UPDATE、DELETE ROW Binlog，并在 Redis 保存进度。
- [ ] 转换插件清理 Markdown、图片占位符和代码，规范化标签并生成标题拼音与首字母。
- [ ] 后端固定追加 `status = 3`，客户端不能覆盖；草稿和软删除文档不得公开返回。
- [ ] 字段优先级、高亮、裁剪、分页及搜索不可用时的错误行为符合功能文档。

## T14 搜索全量刷新与恢复（[#15](https://github.com/Tlfff/ai-blog/issues/15)）

**交付内容**：运维人员可以无中断地全量刷新搜索索引，并在增量进程中断后恢复同步和检查一致性。

**阻塞于**：T13 Meilisearch 搜索与增量同步。

- [ ] `refresh -t articles` 使用临时索引、正式索引设置和相同转换插件导入文章全表。
- [ ] 刷新成功后通过 Index Swap 原子交换，失败时线上 `articles` 索引保持不变。
- [ ] `check -t articles` 核对 MySQL 文章数和索引结果，旧临时索引按规则清理。
- [ ] 增量进程可暂停、恢复并从 Redis 进度继续，不新增 MySQL 搜索字段或同步表。

## T15 gRPC 认证与用户查询（[#16](https://github.com/Tlfff/ai-blog/issues/16)）

**交付内容**：内部服务和外部合作方可以通过不同认证方式调用用户查询 RPC。

**阻塞于**：T03 账号安全与头像上传。

- [ ] 内部请求使用 HS256 JWT 并校验签发者、签名和过期时间。
- [ ] 外部请求使用 HMAC-SHA256，并通过时间窗口和 Redis Nonce 防重放。
- [ ] 用户基本信息和公开信息 RPC 只调用用户上下文公开应用接口。
- [ ] 认证失败返回标准 gRPC 状态，敏感凭据不写日志。

## T16 文章与评论 gRPC 查询（[#17](https://github.com/Tlfff/ai-blog/issues/17)）

**交付内容**：认证调用方可以通过 gRPC 查询已发表文章列表和评论统计。

**阻塞于**：T07 文章列表、浏览与热榜；T09 评论删除与文章评论数；T15 gRPC 认证与用户查询。

- [ ] 文章 RPC 只返回已发表文章并兼容既定 Offset 分页契约。
- [ ] 评论 RPC 返回点赞数及 `点赞数 + 回复数` 热度值。
- [ ] RPC 通过对应上下文公开应用接口获取数据，不直接访问其他上下文仓储。
- [ ] HTTP、gRPC、Consumer 和 Job 统一接入 Leo Runner、Actuator、日志及优雅退出。

## T17 跨上下文验收与故障恢复（[#18](https://github.com/Tlfff/ai-blog/issues/18)）

**交付内容**：通过真实基础设施证明六个限界上下文能够协作，并提供异步投影和搜索同步的故障恢复能力。

**阻塞于**：T06、T07、T09、T10、T11、T12、T14、T16。

- [ ] 验证评论创建到文章评论数、点赞到计数与通知、浏览到历史与热榜的端到端链路。
- [ ] 业务事件链路覆盖重复消息、暂时失败、重试、死信、对账和投影修复。
- [ ] 搜索链路覆盖 Binlog 增量、Redis 进度恢复、Index Swap 和数量检查。
- [ ] 除 Meilisync 只读文章表/Binlog 契约外，不存在跨上下文仓储依赖或跨库直写；全仓库测试和静态检查通过。
