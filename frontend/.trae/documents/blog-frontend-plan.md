## 三、技术方案要点

### 3.1 组件拆分原则
- 页面级组件放在 `app/` 目录
- 可复用组件放在 `components/` 目录，按功能分类
- 每个组件单一职责，不超过 200 行代码

### 3.2 状态管理
- 使用 SWR 进行数据获取和缓存
- 使用 useState 管理本地交互状态（展开/收起、排序等）
- 使用 AuthContext 管理用户认证状态

### 3.3 Mock 数据策略
- 所有交互使用现有 mock API，不连接真实后端
- 数据更新在内存 store 中完成，刷新页面重置
- 保持 API 接口设计与后端一致，便于后续接入

### 3.4 样式规范
- 使用 Tailwind CSS 4，保持与现有代码风格一致
- 优先使用 `cn()` 工具函数组合类名
- 不引入额外样式库

## 四、风险与注意事项

1. **路由冲突**: 注意 Next.js App Router 的路由规则，避免嵌套路由冲突
2. **认证权限**: 管理后台页面需要检查用户角色，非管理员应重定向
3. **数据一致性**: Mock 数据使用内存 store，确保状态更新正确
4. **代码复用**: 优先复用现有组件（如 Card、Button、Avatar 等）
5. **TypeScript 类型**: 确保所有组件和 API 返回值都有正确的类型定义
